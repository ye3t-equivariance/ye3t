Young And Primitive Construction
================================

The core package exposes both exact Young-sector machinery and reduced
primitive quotient machinery.  The important boundary is:

``full exact``
   Enumerate and couple the whole projected exact sector for the requested
   ``n_in``, ``l_in``, permutation representation, and target ``L_R``.

``primitive quotient``
   Keep a complement of the exact sector after removing products generated by
   lower-order factors in the same resolved sector.

``decomposable reconstruction``
   Rebuild higher-order products from primitive generators and exact product
   paths.  This is the reduced route used by primitive-first schedules and
   message-passing layers.

Young Orthogonal Couplings
--------------------------

Use ``young_orthogonal_induced_coupling`` when the caller needs the actual
lowered Young/change-of-group coupling tensor.  The validation helpers check
that the induced bases and product maps obey the expected permutation-sector
compatibility boundary.

.. code-block:: python

   from ye3t import Partition, young_orthogonal_induced_coupling

   coupling = young_orthogonal_induced_coupling(
       Partition((1,)),
       Partition((1,)),
       Partition((2,)),
   )

   print(coupling.left_partition, coupling.right_partition, coupling.target_partition)
   print(coupling.coefficient_matrix().shape)

Rank-2 Young-Yamanouchi / CG Runtime Schedules
----------------------------------------------

Use ``compile_young_yamanouchi_pair_cg_runtime_schedule`` for the first
materialized runtime bridge between the Young-sector convention and executable
coefficient tensors.  The current implementation supports repeated rank-2
slots.  It combines Young-orthogonal Specht induction coefficients with exact
YE3T Clebsch-Gordan coefficients and returns sparse bilinear entries that can
be evaluated by ``evaluate_young_yamanouchi_pair_cg_runtime_schedule``.
The emitted rows are the coefficients that remain after Young symmetrization
and CG recoupling have been summed.  For example, with two repeated ``l=1``
slots, ``(2)`` appears only at ``L_R=0,2`` and ``(1,1)`` appears only at
``L_R=1``.

This is intended for small, controlled filtered-density ``A_s`` ablations where
the goal is to compare trivial and nontrivial slot characters with an explicit
coefficient convention.  It is not yet an arbitrary-rank Young-E3 coefficient
materializer.

.. code-block:: python

   from ye3t import (
       compile_young_yamanouchi_pair_cg_runtime_schedule,
       evaluate_young_yamanouchi_pair_cg_runtime_schedule,
   )

   schedule = compile_young_yamanouchi_pair_cg_runtime_schedule(
       (1, 1),
       (1, 1),
       target_partitions=("trivial", "sign"),
       target_Ls=(0, 1, 2),
   )

References for the mathematical setting:

* R. de Mello Koch, N. Ives, and M. Stephanou, "On subgroup adapted bases for
  representations of the symmetric group", arXiv:1112.4316,
  DOI: 10.1088/1751-8113/45/13/135204.  This paper is relevant to
  Young-Yamanouchi and subgroup-adapted split-basis subduction coefficients;
  this package does not implement its large-row-difference algorithm.
* V. Chilla, "On the linear equation method for the subduction problem in
  symmetric groups", arXiv:math-ph/0512011.  This is used as reference context
  for subduction graphs associated with the Young-Yamanouchi/split-basis
  equation system.
* V. Chilla, "A reduced subduction graph and higher multiplicity in S_n
  transformation coefficients", arXiv:math-ph/0606037.  This is used as
  reference context for reduced subduction graphs, selection/identity rules,
  and higher-multiplicity cases; the current implementation is a finite-rank
  YE3T-specific graph-propagation backend, not a full reproduction of every
  algorithm in that paper.

Schur-Weyl-Guided Balanced Runtime Trees
----------------------------------------

Status: implemented and tested for selected finite cases; not yet an
independent arbitrary-rank normalized Young-Yamanouchi subduction-coefficient
generator.

Use ``compile_schur_weyl_guided_tree_product`` when inspecting balanced
pairwise runtime schedule shapes beyond rank 2.  Each internal node first
builds the cached ``young_specht_basis_construction_plan`` for its span and
then requests only those admissible target labels from the existing exact
``JointYoungCGProduct`` lowering path.  The compiler validates that the
materialized node dimension matches the selected Schur-Weyl/Specht plan and
that no requested target labels are missing or duplicated.

``JointYoungCGProduct`` now emits fused irreducible target blocks.  When
multiple pairwise branches land in the same canonical final label, the runtime
uses one output block and accumulates the exact branch coordinate maps into
that block.  It does not expose an unfused coupling-path output mode.

Root parity can be filtered with ``root_target_parity="even"`` or
``root_target_parity="odd"``.  This uses the total slot parity
``(-1)^{sum_i l_i}``; the default ``None`` keeps all ``SO(3)`` sectors.

Validated cases currently include:

* rank-3 non-repeated slots, e.g. ``nin=(1,1,1)``,
  ``lin=(0,1,2)``, with exact runtime dimension matching the plan dimension;
* rank-4 balanced scalar slots, e.g. ``lin=(0,0,0,0)``, with exact runtime
  dimension matching the plan dimension.
* rank-3 repeated slots ``nin=(1,1,1)``, ``lin=(1,1,1)``, with fused runtime
  dimension ``27`` matching the Schur-Weyl/Specht plan dimension.

``littlewood_richardson_tableaux`` and
``littlewood_richardson_coefficient`` now provide an independent exact
finite-rank multiplicity-label route for one subgroup-adapted merge
``S_a x S_b -> S_{a+b}``.  The coupling constructor checks that the LR
coefficient agrees with the character inner product and the exact
Young-orthogonal intertwiner dimension before returning a tensor.  This
implements LR multiplicity labeling and validation; it does not yet derive
normalized subduction coefficient matrices directly from LR tableaux.

``littlewood_richardson_chain_labels`` extends this multiplicity-label route
to an arbitrary number of subgroup factors using a left-associated chain of
LR tableaux.  For the trivial permutation sector,
``trivial_symmetric_subduction_coefficients`` gives a constructive normalized
coefficient vector for any Young subgroup
``S_{a_1} x ... x S_{a_k} -> S_N``: the coefficient vector is the constant
orbit sum over left cosets, normalized by ``[S_N : S_{a_1} x ... x S_{a_k}]``.
This n-ary trivial-sector path is constructive.

``young_orthogonal_nary_subduction`` materializes n-ary subgroup-adapted
coefficient matrices in the direct induced basis for trivial and nontrivial
Specht sectors.  It supports ``bracketing="balanced"``, ``"left"``, and
``"right"`` for the attached LR-chain labels.  The default
``coefficient_backend="subduction_graph"`` constructs nontrivial finite-rank
coefficients from exact Young-subgroup generator constraints by deterministic
component propagation and exact multiplicity-space normalization.  It raises
if propagation cannot resolve the requested finite case; it does not silently
fall back to the oracle.  ``coefficient_backend="intertwiner_oracle"`` keeps
the older exact symbolic intertwiner/nullspace path available for reference
validation only.  LR chains provide bracketing-aware multiplicity labels, but
they are not claimed to be a closed formula for normalized coefficient
entries.  ``validate_young_orthogonal_nary_subduction_coherence`` checks
associativity/coherence across bracketings by comparing the projectors
``C C^T`` onto the target isotypic subspace and the orthogonality of the
recoupling overlap matrices.  Coherence in this sense means that different
parenthesizations may choose different multiplicity bases, but they span the
same subspace of the same n-ary induced representation.
``validate_young_orthogonal_nary_subduction_coherence_up_to_rank`` runs the
same check over enumerated small-rank cases; current tests exercise this
through rank 4.

Remaining limitation: the current fused runtime reuses exact lowered
coordinate maps from the existing generalized composer and coalesces them by
canonical target label.  The subduction-graph backend is implemented and
tested on small finite-rank cases, including a binary multiplicity-two case,
but it is not yet benchmarked and should not be described as production
optimized.

Balanced Message-Passing Reference Schedules
--------------------------------------------

Status: schedule/reference/state-view implemented under validation; full
recursive tensor message passing remains planned and not public.

``CompileBalancedYE3TMessagePassingSchedule`` consumes a
``BalancedYE3TMessageStateSpec`` and expands each requested hidden sector into
certified global Young--E3 coupler records.  The schedule records the task
readout selection rule, selected coefficient backend, repeated-content image-map
metadata when needed, and balanced-tree certificates.  It intentionally keeps
``implemented_tensor_runtime=False`` and
``full_message_passing_runtime_status="planned_not_public"``.
For repeated-content balanced splits, ``RepeatedContentImageMap`` exposes both
the image isometry table ``S`` and the image projector ``P = S S^T``.  The
validation report checks orthonormal image columns, projector idempotency,
agreement between ``P`` and ``S S^T``, image dimension, direct global-coupler
agreement, and that no descriptor-level SVD/reduction is used.

``EvaluateBalancedYE3TMessagePassingScheduleReference`` applies the scheduled
sector coefficient tables to caller-supplied tensors.  This reference evaluator
does not aggregate messages, apply nonlinear hidden updates, apply a
readout, evaluate energies or forces, or assemble fermion operators.

``PackageBalancedYE3TMessagePassingReferenceState`` and the convenience method
``BalancedYE3TMessagePassingReferenceEvaluation.to_direct_sum_state_view``
concatenate evaluated sector outputs into a direct-sum state view with explicit
layer, content, target partition, coefficient-axis, and slice metadata.  This
is useful for checking hidden-state layout and descriptor/model API wiring.
``BalancedYE3TMessageStateReferenceView.to_tensor_container()`` returns a
validated ``BalancedYE3TMessageStateTensorContainer`` with contiguous sector
slices, target partitions, coefficient axes, and feature-axis coverage checks.
``BalancedYE3TMessageStateTensorContainer.apply_message_sum_aggregation(...)``
applies incoming-edge sum aggregation along a node/site/particle axis while
preserving the Young--E3 feature axis and sector slices.
``BalancedYE3TMessageStateTensorContainer.apply_sectorwise_scalar_update(...)``
applies one scalar intertwiner per sector while preserving the sector slices
and avoiding cross-sector or representation-coordinate mixing.
``BalancedYE3TMessageStateTensorContainer.apply_channel_linear_update(...)``
applies a linear map along an explicit channel or multiplicity axis while
preserving the Young--E3 feature axis and sector slices.  This primitive assumes
that the selected channel axis carries trivial group action; it is not a general
representation-coordinate map.
``BalancedYE3TMessageStateTensorContainer.apply_channel_linear_reference_message_layer(...)``
composes incoming-edge sum aggregation with that channel-axis map, and
``BalancedYE3TChannelLinearReferenceMessageLayer.initialize(...)`` creates the
corresponding parameterized reference object.
``BalancedYE3TMessageStateTensorContainer.apply_reference_message_layer(...)``
composes those two primitives into an incoming-edge-sum-plus-sector-scalar
linear reference layer.  ``BalancedYE3TReferenceMessageLayer.initialize(...)``
creates the corresponding parameterized reference object with one scalar gain
per retained sector.
Its status string is
``direct_sum_coefficient_state_view_not_recursive_message_runtime``; it should
not be described as a balanced recursive message-passing runtime.

.. code-block:: python

   from ye3t.api import compile_schur_weyl_guided_tree_product

   tree = compile_schur_weyl_guided_tree_product((1, 1, 1), (0, 1, 2))
   print(tree.dim)
   print(tree.static_schedule_report()["nodes"][-1]["dimension_matches_plan"])

   odd_scalar = compile_schur_weyl_guided_tree_product(
       (1, 1, 1),
       (1, 1, 1),
       root_target_Ls=(0,),
       root_target_parity="odd",
   )

Primitive Quotients
-------------------

Use ``young_resolved_primitive_quotient`` when the goal is to decide which
projected exact basis vectors remain as new generators after lower-generated
products have been removed.  The output records full rank, generated rank,
primitive rank, and validation metadata for the selected sector.

The quotient should be called directly only for mathematical audits,
enumeration tools, or new runtime lowering work.  User-facing descriptor and
message-passing workflows normally enter through higher-level helpers such as
``build_operator_ir`` in core or the ACE descriptor/message APIs in
``ye3t-ace`` (separate package, not yet public).
